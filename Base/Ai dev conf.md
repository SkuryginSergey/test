## AI опыт рустора 

![[Pasted image 20260524163558.png]]

### метрики 
 - Компания использует фреймворки DX Core 4 и DX4AI от создателей DORA-метрик
 - Для атрибуции кода (что написал AI, а что человек) используются хуки Claude Code и OpenCode: каждый промт вызывает события, данные о токенах отправляются в сервис, где через git blame происходит разметка кода.
### антипаттерны
 - зоопарк инструментов
 - отсутствие разметки метрик
 - редкие или отсутствующие обучения
 - отсутствие человека на ревью AI-кода
 - устаревший agents.md
### что работает
 - сбор команды (3–5 человек)
 - подготовка инфраструктуры и доставки тулов
 - обучение, выстраивание коммуникаций
 - сбор фидбэка
 - обязательный сбор метрик.

## Внедрение AI-агентов: что показывают пилоты 
 - Метрики собираются с точки зрения инструмента: чат-логи, вызовы тулов, телеметрия из IDE
 - LLM Judge оценивает реальное время решения задачи, классифицирует её и сравнивает время человека и агента. Можно посчитать процент принятия кода — сравнить предложенное агентами с тем, что попало в коммит

## Единая среда обитания для AI и продуктовых команд
### копилоты для ролей
Должен быть набор агентов для каждой роли
- Копилот для аналитика по описанному требованию выдавал оценку от 0 до 10 и комментарии о том, что не учтено. Оценка задумывалась для геймификации, но команды стали использовать её как quality gate — например, не передавать требования в разработку, если оценка ниже восьми.
 - Копилот для разработчика — стандартная история. 
 - Копилот для тестировщика описывал по лучшим практикам тест-дизайна набор функциональных тестов, давая «хладнокровную» оценку, сколько тестов и каких должно быть
