ИИ-помощник должен:
 - [0] строить выражения с учетом локализованных свойств и функций

 ИИ-помощник должен уметь использовать в выражениях следующие элементы:
  - [0] группы вложений
  - [1] Констраинты для групп вложений 
  - [0] свойства сущностей, включая свойства ссылки
  - [0] свойства сущностей с учетом возможных наследников от базового объекта. Например, если свойство recipient, то должны вывести свойства для сущностей сотрудников, подразделений групп и т.д.
  - [1] свойства коллекции
  - [1] ноукод свойства сущностей, через параметры сущностей
  - [1] функции выражений
  - [1] параметры процессов

Примеры выражений:
 - Задача→ План→ Внутренние планы работ→ Первый элемент → Проект → Куратор
	 - Хочется написать ИИ: "напиши выражение для определения куратора внутреннего плана"		
 - Задача → Получить локализованную строку схемы маршрута(Subject_SE_3) → Формат(Задача → Документ → Все вложения → Первый элемент → Имя)
	 - локализация: "Subject_SE_3": { "ru-RU": "Подпишите: {0}"}
	 - Хочется написать ИИ: Напиши выражение для темы в виде "Подпишите: <Имя  основного документа>" 		 
 - "Задача → Получить локализованную строку схемы маршрута(Subject_SE_4) → Формат(Задача → Авансовый отчет → Все вложения → Первый элемент → Рег. №, Задача → Авансовый отчет → Все вложения → Первый элемент → Дата документа → Дата без времени, Задача → Сотрудник → ФИО, Задача → Авансовый отчет → Все вложения → Первый элемент → Назначение аванса)",
	 - локализация "Subject_SE_4": {  "ru-RU": "Согласуйте авансовый отчет №{0} от {1} {2} за {3}"   }
 - "Задача → Получить локализованную строку схемы маршрута(Subject_SE_11) → Формат(Задача → Обращение → Номер, Задача → Обращение → Описание → Обрезать до N символов(50))" 
	 - локализация "Subject_SE_11": { "ru-RU": "Проведите работы по обращению {0} \"{1}\"",    },
	 - обрезать до N символов - это функция


# Запросы для проверки сколько токенов жрет

с полным контекстом на каждый ушло порядка 3000 токенов
**запрос 1**:
давай переделаем опредление дочерней коллекции, ее определяем не по первому навигационному свойству, а так: 
- в свойстве сущности дочерняя коллекция определяется свойством с типом CollectionPropertyMetadata 
- в нем есть ссылка на дочернюю сущность в свойстве EntityGuid
- по этой ссылке находим сущность и выводим ее в подразделе к сущности как я писал выше. 
- из дочерней сущности удаляем свойство со ссылкой на родительскую сущность
- из названия дочерней сущности удаляем название родительской сущности

**запрос 2**:
отлично. Теперь для типа collection добавь ссылку на дочернюю коллекцию как для сылочных свойств, а в описании дочерней коллекции добавь ссылку на родителскую сущность. 
Пример было: 
- **GUID:** `619fd305-b53b-4797-8c25-2a2a706b6c0c` 
должно стать: 
- дочерняя коллекция для типа: <ссылка на тип>
- **GUID:** `619fd305-b53b-4797-8c25-2a2a706b6c0c`
